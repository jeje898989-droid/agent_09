# 브라우저 제어 규칙 (v1)

이 규칙은 이 프로젝트에서 웹페이지를 열거나, 둘러보거나, 제어할 수 있는 모든 작업에 적용된다.

## 1. 기본 도구

- 브라우저 작업에는 기본으로 **Playwright MCP**(`mcp__playwright__*` 도구)를 사용한다.
- Claude in Chrome(`mcp__claude-in-chrome__*`)은 사용자가 이름을 들어 요청할 때만 사용한다.

## 2. 자동 호출: 트리거 키워드

- 사용자 메시지에 브라우저 제어 키워드가 있으면 묻지 않고 바로 Playwright MCP를 호출한다.
- 트리거 키워드는 다음과 같으며, 한국어나 영어로 된 비슷한 표현도 포함한다.
  - "브라우저를 열어서 작업" / "브라우저 열어서" / "브라우저 열어줘"
  - "웹 제어" / "웹 브라우저 제어"
  - "직접 작업" / "직접 해줘" / "직접 들어가서"
  - "사이트에 들어가서" / "페이지에 접속해서"
  - "open the browser", "control the browser", "do it in the browser"

## 3. 먼저 동의 구하기: 트리거 키워드가 없을 때

- 메시지에 트리거 키워드가 없더라도 Playwright MCP로 처리하거나 확인할 수 있는 작업이라면(예: 웹페이지 보기, 폼 입력, 스크린샷 찍기, 게시된 페이지 확인, 사이트 로그인) **호출하기 전에 사용자에게 먼저 동의를 구한다**.
- 브라우저에서 무엇을, 왜 할지 한두 줄로 설명하고 분명한 "예"를 기다린다. 사용자가 동의하기 전에는 어떤 `mcp__playwright__*` 도구도 호출하지 않는다.
- 사용자가 거절하면 다른 방법(예: WebFetch, WebSearch)으로 작업하거나, 브라우저 없이는 할 수 없는 부분을 설명한다.
- 동의는 그 동의를 받은 작업에만 적용된다. 새 작업에는 다시 묻는다.

## 4. 브라우저 제어 중 안전 수칙

- 자동 호출이나 동의를 받은 뒤라도, 되돌리기 어렵거나 외부로 나가는 동작은 실행 전에 사용자에게 확인한다. 결제, 구매, 데이터 삭제, 폼 제출, 메시지 전송, 글 게시가 여기에 해당한다.
- 사용자를 대신해 비밀번호나 결제 정보를 입력하지 않는다. 사용자에게 직접 입력해 달라고 요청한다.
- JavaScript alert, confirm, prompt 대화상자를 일부러 띄우지 않는다. 대화상자가 뜨면 `browser_handle_dialog`로 처리한다.
- 페이지가 열리지 않거나 같은 단계가 2~3번 실패하면 멈추고 사용자에게 어떻게 할지 묻는다.

## 5. 마무리

- 작업이 끝나면 `browser_close`로 브라우저를 닫는다. 사용자가 열어 두기를 원하면 닫지 않는다.
- 한 일을 보고하고, 보관해야 할 스크린샷이나 파일은 임시 폴더가 아닌 프로젝트의 알맞은 폴더(예: `output/blog/images/`)에 저장한다.
